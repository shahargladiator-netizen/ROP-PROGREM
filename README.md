מסמך אפיון טכני: RoP Tracker – Goldberg Academy
1.סקירה כללית על המוצר
אפליקציית ניהול אימונים אישית המיועדת למתאמני כוח בשיטת Rite of Passage (מתוך הספר Enter the Kettlebell!). האפליקציה פועלת במתכונת של ניהול עצמי (Standalone) ללא צורך בשרת ניהול או בקרה מרכזית של מנהל. המטרה היא לאפשר למתאמן לפרוס את נפח האימון לאורך היום ("שימון התנועה"), לעקוב אחר סולמות הלחיצות (רנגים), ולנהל תרגילי השלמה.

2. מסכי האפליקציה וזרימת משתמש (User Flow)
א. מסך פתיחה / Onboarding (מוצג בפעם הראשונה)
חלק עליון: כותרת ראשית ותיאור קצר של האקדמיה ושל התוכנית.

סרטוני הדרכה (YouTube Embeds):

סרטון 1: מבוא כללי לתוכנית, התפלגות העומס (קל, בינוני, כבד), שילוב תרגילים משלימים (סקוואט וסווינגים) ודרכי התקדמות.

סרטון 2: הסבר מפורט על מה זה "רנג", איך מבצעים רנג שלם, וההיגיון הפיזיולוגי של פריסת האימון לאורך היום.

כפתור פעולה: "הבנתי, בוא נתחיל!" (סוגר את מסך ההדרכה ומעביר למסך הראשי).

ב. מסך הבית הראשי (Dashboard)
Context Bar (חלק עליון קבוע):

כפתור גישה לספריית הווידאו.

כפתור הגדרות (Settings).

תצוגת סטטוס נוכחית: מספר השבוע בתוכנית (למשל: שבוע 4) וסוג היום (קל / בינוני / כבד).

מונה התקדמות יומית (למשל: סך הרנגים שבוצעו מתוך סך הכל) בתוספת פס התקדמות (Progress Bar) דינמי.

גוף המסך (רנגים וסולמות):

הצגת הסולמות היומיים בהתאם לטבלת 13 השבועות.

לכל רנג יש שורת ביצוע הכוללת: מספר הרנג (למשל 1, 2, 3, 4), ותיבות סימון (Checkboxes) נפרדות עבור Clean & Press (C&P) ועבור מתח.

אזור תרגילי השלמה (רשות):

מקטע ייעודי בתחתית המסך עבור סווינגים ועבור סקוואט.

כל תרגיל כולל: תיבת סימון "בוצע", שדה להזנת משקל (ק"ג) ושדה להזנת חזרות/סטים.

ג. מסך הגדרות (Settings)
פעולות מהירות (Shortcuts):

סמן אימון זה כבוצע (דלג): ממלא אוטומטית את כל ה-V של אותו יום ומפעיל את אנימציית הסיום.

סמן שבוע שלם כבוצע (דלג): מקדם את ספירת השבועות ומפעיל את חלון "שבוע חדש".

3. לוגיקה עסקית ומצבים מיוחדים (Business Logic)
מעבר שבוע / אימון ראשון בשבוע:

בכניסה לשבוע חדש, או בעקבות דילוג שבוע, יופיע חלון קופץ (Modal) עם הכותרת: "שבוע חדש יוצא לדרך!" והטקסט: "מתחילים שבוע חדש עם נפח עבודה חדש, בהצלחה."

חגיגת סיום אימון / שבוע / תוכנית (Gamification):

ברגע שכל המשימות היומיות סומנו כבוצעו, המערכת מפעילה אנימציית קונפטי על המסך ומציגה חלון הצלחה ("כל הכבוד!") המשתנה בהתאם להקשר:

אימון רגיל / בינוני: "סיימת את האימון."

אימון סוף השבוע (הכבד): "סיימת את התוכנית השבועית."

סיום שבוע 13 (אימון כבד אחרון בתוכנית): מציג את הודעת הסיכום: "סיימת את התוכנית עם משקל [X] ק"ג שבוצע כל התוכנית. בתוכנית הבאה אתה ממשיך עם המשקל החדש מההתחלה."

התנהגות בימים שאינם מושלמים:

במידה ומתאמן לא הספיק לסיים את כל הרנגים ביום מסוים, המערכת שומרת את הביצוע החלקי ומאפשרת למתאמן לעבור ליום האימון הבא בלחיצת כפתור או באופן אוטומטי (ללא גרירת חובות נפח).

ניהול משקל עבודה:

המתאמן מגדיר את משקל הקטלבל פעם אחת בתחילת התוכנית, והוא מוזן אוטומטית ברנגים (ללא צורך בהקלדה חוזרת לאורך היום, מלבד אפשרות עריכה במקרה של הצורך ברגרסיה).

4. דרישות טכנולוגיות מומלצות למפתח
ארכיטקטורה: אפליקציית מובייל חוצת פלטפורמות (Cross-Platform) כמו Flutter או React Native, לחלופין פיתוח כ-Progressive Web App (PWA) מבוסס טכנולוגיות Web מתקדמות.

אחסון מקומי (Local Storage): שמירת נתוני התקדמות המתאמן, השבוע הנוכחי ומשקלי העבודה על גבי המכשיר (Local Storage / SQLite) מאחר ואין צורך בשרת חיצוני.

ספריות עיצוב: שימוש בספריות עיצוב מודרניות (כגון Tailwind CSS לפיתוח Web או Native Components במובייל) לשמירה על ממשק כהה (Dark Mode) נקי עם דגשים בצבע כתב קלאסי של האקדמיה.
